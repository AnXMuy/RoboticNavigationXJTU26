# RoboticNavigation 运行说明（实机 + 仿真）

本文档对应当前仓库 `src/`，覆盖实验 2~5 的双模式运行，并支持“仿真/实车解耦”。

## 1. 环境与编译

```bash
cd /Users/zixuan/XJTU/RoboticNavigation
eval "$(conda shell.zsh hook)"
conda activate ros1_noetic
export ROS_PACKAGE_PATH="$PWD/src:${ROS_PACKAGE_PATH:-}"
```

### 1.1 仿真专用构建（推荐 PC 无实车时使用）

```bash
./tools/use_sim_profile.sh
./tools/show_build_profile.sh
catkin_make
source devel/setup.bash
```

### 1.2 实车构建

```bash
./tools/use_real_profile.sh
./tools/show_build_profile.sh
catkin_make
source devel/setup.bash
```

## 2. 实验 2（RViz 键控模型）

```bash
roslaunch vehicle_sim vehicle_sim_rviz.launch
```

说明：
- 默认会启动 `joint_state_publisher_gui`、`robot_state_publisher`、`vehicle_sim_node` 与 RViz。
- 若只想自动发布关节，不弹 GUI：`use_gui:=false`。

## 6. 进阶参数入口

- Hector 分辨率对比（实验 3）：
  - `resolution_profile:=fine|coarse|baseline`
  - 示例：`roslaunch ebot_bringup slam_hector.launch mode:=sim resolution_profile:=fine`
- AMCL 参数档位（实验 4）：
  - `amcl_profile:=baseline|fast|robust`
- 规划器切换（实验 5）：
  - `global_planner:=navfn/NavfnROS|global_planner/GlobalPlanner`
  - `local_planner:=base_local_planner/TrajectoryPlannerROS|dwa_local_planner/DWAPlannerROS`
- 代价地图对比（实验 5）：
  - `costmap_profile_file:=<yaml绝对路径或$(find ...)>`
  - 示例（保守）：`costmap_profile_file:=$(find ebot_bringup)/config/navigation/costmap_common_sim_conservative.yaml`

## 7. 地图文件要求

`map_server` 默认加载：
- `src/ebot_bringup/maps/nav.yaml`
- `src/ebot_bringup/maps/nav.pgm`

如果文件名不同，使用 `map:=<your_map.yaml>` 覆盖。

## 8. 双模式约定

- `mode:=real`：默认值，保留原实机流程。
- `mode:=sim`：启用 Gazebo 仿真链路，不启动实机串口驱动与实机雷达驱动。

## 9. 仿真雷达排障（重要）

在部分非 Ubuntu20.04 原生 Noetic 环境（例如 Conda + macOS）下，可能出现：
- Gazebo 内部已有雷达数据（`gz topic -l` 可见 `.../rplidar/scan`）
- ROS 侧没有 `/scan`

建议优先使用课程要求的 Ubuntu20.04 + ROS Noetic 环境执行实验 3~5 的仿真链路。
