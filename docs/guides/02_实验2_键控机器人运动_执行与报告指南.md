# 实验2 键控机器人运动：执行与报告指南

对应文档：`docs/实验指导书-实验2_键控机器人运动.pdf`

## 0. 环境准备

```bash
cd /Users/zixuan/XJTU/RoboticNavigation
eval "$(conda shell.zsh hook)"
conda activate ros1_noetic
export ROS_PACKAGE_PATH="$PWD/src:${ROS_PACKAGE_PATH:-}"
source devel/setup.bash
```

如未安装键盘控制包：

```bash
sudo apt install ros-noetic-teleop-twist-keyboard
```

预期结果：
- `rosversion -d` 输出 `noetic`。
- `rospack find vehicle_sim`、`rospack find teleop_twist_keyboard` 可返回路径。

## 1. 仿真实验（主线，PC 可独立完成）

### 1.1 仅启用仿真构建档位（解耦实车依赖）

```bash
./tools/use_sim_profile.sh
./tools/show_build_profile.sh
catkin_make
source devel/setup.bash
```

预期结果：
- `show_build_profile.sh` 显示 `turn_on_wheeltec_robot`、`ydlidar_ros_driver`、`rf2o_laser_odometry` 为 `SIM_ONLY`。
- `catkin_make` 成功完成（若编译器环境限制导致失败，先按课程标准 Ubuntu20.04+Noetic 复现）。

### 1.2 启动 RViz 模型与简化里程计节点

终端A：
```bash
roslaunch vehicle_sim vehicle_sim_rviz.launch
```

预期结果：
- RViz 打开后可看到小车模型。
- 节点存在：`/vehicle_sim_node`、`/robot_state_publisher`。

### 1.3 检查话题与 TF

终端B：
```bash
rostopic list | rg '^/cmd_vel$|^/odom$|^/tf$|^/tf_static$'
rostopic echo -n 1 /odom
rosrun tf2_tools view_frames.py
```

预期结果：
- 至少看到 `/cmd_vel`、`/odom`、`/tf`。
- `/odom` 消息 `header.frame_id` 为 `odom`，`child_frame_id` 为 `base_footprint`。
- 生成 `frames.pdf`，可看到 `odom -> base_footprint` 变换链。

### 1.4 键盘控制运动

终端C：
```bash
rosrun teleop_twist_keyboard teleop_twist_keyboard.py
```

按 `i/j/l/k` 等按键控制，另开终端D观测：

```bash
rostopic echo /cmd_vel
```

预期结果：
- 键盘按键时 `/cmd_vel` 连续变化。
- RViz 中模型位姿随控制变化，`/odom` 持续更新。

## 2. 文档“实验要求”逐项验收

### 2.1 要求：完善 `vehicle_sim.py`，发布里程计与 TF

核验命令：

```bash
rosnode info /vehicle_sim_node
rostopic hz /odom
```

通过标准：
- `/vehicle_sim_node` 订阅 `/cmd_vel`，发布 `/odom`。
- `/odom` 频率稳定（通常约 50Hz）。

### 2.2 要求：查看 TF 树结构

核验命令：

```bash
rosrun tf2_tools view_frames.py
```

通过标准：
- 生成 `frames.pdf`，能看到与底盘相关的 TF 关系。

## 3. 实车实验（可选，需硬件）

如果你连接实车与雷达，执行：

终端A：
```bash
./tools/use_real_profile.sh
catkin_make
source devel/setup.bash
roslaunch ebot_bringup bringup.launch mode:=real
```

终端B：
```bash
rosrun teleop_twist_keyboard teleop_twist_keyboard.py
```

终端C（TF核验）：
```bash
rosrun tf2_tools view_frames.py
```

预期结果：
- 小车底盘响应键控。
- TF 树可见 `base_footprint` 到车体相关坐标系。

## 4. 实验报告取证清单

建议至少包含：
- RViz 中 RobotModel + TF 的截图。
- `/odom` 与 `/cmd_vel` 的终端输出截图。
- `frames.pdf`（或 `rqt_tf_tree`）截图。
- 关键 launch（`vehicle_sim_rviz.launch`）与核心脚本（`vehicle_sim.py`）关键片段。

## 5. 常见问题

- `teleop_twist_keyboard` 未安装：执行 `sudo apt install ros-noetic-teleop-twist-keyboard`。
- RViz 无模型：检查 `robot_description` 是否加载成功，确认 `source devel/setup.bash` 已执行。
- `/odom` 不更新：确认 `vehicle_sim_node` 正在运行并且 `cmd_vel_timeout` 未配置过小。
