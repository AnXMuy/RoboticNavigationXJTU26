## 3. 文档“进阶实验”四项实现

### 3.1 代价地图参数调优对比（保守 vs 激进）

保守参数（大膨胀）：

```bash
roslaunch ebot_bringup test_nav.launch \
  mode:=sim map:=nav.yaml \
  costmap_profile_file:=$(rospack find ebot_bringup)/config/navigation/costmap_common_sim_conservative.yaml
```

激进参数（小膨胀）：

```bash
roslaunch ebot_bringup test_nav.launch \
  mode:=sim map:=nav.yaml \
  costmap_profile_file:=$(rospack find ebot_bringup)/config/navigation/costmap_common_sim_aggressive.yaml
```

对比观察：
- 狭窄通道中路径是否更贴边。
- 避障安全裕度（是否更保守绕远）。

### 3.2 规划器性能测试与对比

组合A（Navfn + TrajectoryPlanner）：

```bash
roslaunch ebot_bringup test_nav.launch \
  mode:=sim map:=nav.yaml \
  global_planner:=navfn/NavfnROS \
  local_planner:=base_local_planner/TrajectoryPlannerROS
```

组合B（GlobalPlanner + DWA）：

```bash
roslaunch ebot_bringup test_nav.launch \
  mode:=sim map:=nav.yaml \
  global_planner:=global_planner/GlobalPlanner \
  local_planner:=dwa_local_planner/DWAPlannerROS
```

B 组合的 RViz 路径话题：
- 全局：`/move_base/GlobalPlanner/plan`
- 局部：`/move_base/DWAPlannerROS/local_plan`

建议记录：
- 到达总耗时。
- 路径长度与拐弯次数。
- 局部轨迹抖动程度。

### 3.3 动态避障测试

步骤：
1. 先发布一个较远目标点。
2. 导航过程中在机器人前方临时放置障碍（仿真中可拖动物体或插入障碍模型）。
3. 观察局部代价地图与局部路径是否重规划。

核验命令：

```bash
rostopic echo /move_base/local_costmap/costmap_updates
```

通过标准：
- 局部代价地图实时变化。
- 机器人绕行后继续前往目标点。

### 3.4 异常处理与恢复行为验证

测试方法1：设置不可达目标（障碍包围区域内）。

测试方法2：把机器人放进死胡同后再发目标。

监控命令：

```bash
rostopic echo /move_base/status
rostopic echo /move_base/recovery_status
```

通过标准：
- `move_base` 能触发恢复行为（如清理代价地图、旋转恢复）。
- 若仍不可达，状态进入 `ABORTED`，过程可在终端日志中看到。

## 4. 思考题作答素材（可直接引用）

- `2D Nav Goal` 对应话题：`/move_base_simple/goal`。
- 另一种发目标方式：`rostopic pub /move_base_simple/goal ...` 或 action client 调 `/move_base`。
- 全局规划关注静态地图上的宏观最优路径；局部规划关注实时避障和可执行速度。
- 维护全局/局部两张代价地图是为了兼顾全局可达性与局部动态安全性。
- Action 与 Topic/Service 区别：Action 支持长任务反馈、可取消、可查询状态。

## 5. 实验报告取证清单

建议至少包含：
- 基础导航完整截图（map/global_costmap/local_costmap/global_path/local_path）。
- 进阶四项的截图或日志证据：
  - 保守/激进代价地图对比图。
  - 两组规划器轨迹与耗时对比表。
  - 动态障碍触发局部重规划的连续截图。
  - 恢复行为触发日志或 `/move_base/recovery_status` 输出。

## 6. 常见问题

- `/move_base` 启动后无全局路径：先检查 `map:=` 指向的地图是否存在。
- 局部路径不更新：检查 `/scan`、`/odom`、`/tf` 是否完整。
- 目标点点击后无响应：确认 RViz Fixed Frame 为 `map`，并查看 `/move_base/status`。
- 仿真环境无 `/scan`：在非课程标准环境可能出现插件兼容问题，建议切换 Ubuntu20.04+Noetic。
