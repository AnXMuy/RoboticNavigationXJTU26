## 2. 全局前置（建议先做）

```bash
cd /Users/zixuan/XJTU/RoboticNavigation
eval "$(conda shell.zsh hook)"
conda activate ros1_noetic
export ROS_PACKAGE_PATH="$PWD/src:${ROS_PACKAGE_PATH:-}"
export ROS_IP=127.0.0.1
export ROS_HOSTNAME=127.0.0.1
```

如果当前只做仿真（PC 无实车硬件），先切换仿真构建档位：

```bash
./tools/use_sim_profile.sh
./tools/show_build_profile.sh
catkin_make
source devel/setup.bash
```

如果后续要切回实车：

```bash
./tools/use_real_profile.sh
./tools/show_build_profile.sh
catkin_make
source devel/setup.bash
```

## 3. 关于仿真/实车解耦

本仓库已经支持统一入口参数：
- `mode:=sim`：仿真模式，不依赖实车底盘串口和实机雷达驱动。
- `mode:=real`：实车模式，走真实底盘与雷达链路。

核心入口：
- `roslaunch ebot_bringup bringup.launch mode:=sim|real`
- `roslaunch ebot_bringup test_amcl.launch mode:=sim|real ...`
- `roslaunch ebot_bringup test_nav.launch mode:=sim|real ...`

## 4. 环境说明

课程文档标注的软件环境是 Ubuntu20.04 + ROS Noetic。若你在非课程标准环境（例如 Conda + macOS）运行实验 3~5，可能出现 Gazebo 与 ROS 插件兼容差异。遇到异常时按各指南中的“故障排查”节处理。
